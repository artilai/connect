Rules:

- `src/` has three layers and the entry point. `main.ts` reads the environment and brings the built-in channels. `app/` assembles the server: `services.ts` builds every domain's service, `http.ts` mounts the domains' routes, `mcp.ts` builds the MCP server from the domains' tools, `cli.ts` collects the domains' commands, with `server.ts`, `setup.ts`, `context.ts` and `testing.ts` beside them. `domains/<area>/` holds one area of the server each, like `messages`, `agents` or `sign-in`. `platform/` holds what every domain shares and nothing area-specific: the database and its schema, HTTP and MCP helpers, config, storage, crypto, Tailscale and what only Artil Cloud has.
- Every domain has the same shape, with only the files it needs. `schema.ts` holds its API shapes in zod, its record types and the `toX` presenters, one place per shape, shared by routes and tools. `repository.ts` holds SQLite and nothing else: rows in, rows out, no rules and no other domain's repository. `service.ts` holds the domain's use cases and every rule it has; it is what other domains and the adapters use, and it may hand out repository methods as they are. `routes.ts` is the HTTP adapter, named `<surface>.routes.ts` when a domain has several surfaces; `tools.ts` is the MCP adapter, `commands.ts` the CLI adapter and `middleware.ts` its Hono middleware. A file named for one of the domain's own concepts, like `admission.ts`, `stream.ts` or `links.ts`, sits beside them, and `<area>.test.ts` tests the domain.
- An adapter reads its input, calls a service and presents the result. It never imports a repository and decides nothing a service should, so the HTTP API, MCP and the command line act the same way.
- A service or repository never imports `hono`, `@modelcontextprotocol/*` or `@clack/prompts`; what needs them belongs in an adapter.
- A domain reaches another domain only through its `service.ts` or `schema.ts`, types included.
- `platform/` imports no domain and no `app/`, and no domain imports `app/`; tests may import `app/testing.ts` from anywhere.
- `artil/server-architecture` in `.config/lint/index.ts` checks these layers on every lint; fix what it finds rather than working around it.
- A new area is a new folder in `domains/` with the files above; `app/services.ts`, `app/http.ts`, `app/mcp.ts` and `app/cli.ts` then add its service, routes, tools and commands beside the others.
